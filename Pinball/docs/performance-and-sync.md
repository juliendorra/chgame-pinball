# Ramp performance and synchronized play

## Console measurements, 10 November 2026

`tools/benchmark_ramp_device.py` tests the current board exports using RAM-only
fixtures. It preserves SD files, restores the previous RAM board, and restarts
its game afterward. Fixed-camera paused samples isolate rendering; active
samples measure both rendering and physics during a seeded launch. Paused
samples include the pause panel and a full LCD transfer, so they must not be
reported as active gameplay FPS.

With the corrected Orbital Robot gate, before and after the packed ramp-span
optimization (same 1.5-second workload, seed and input sequence):

| Layout | Before Hz | After Hz |
| --- | ---: | ---: |
| Orbital Robot, first two ramps | 59.0 | 60.1 |
| Orbital Robot, all three ramps | 56.7 | 58.7 |
| Orbital Robot stress: 4 ramps | 53.0 | 56.0 |
| Orbital Robot stress: 6 ramps | 45.6 | 49.3 |
| Orbital Robot stress: 8 ramps | 40.9 | 44.2 |
| Orbital Robot stress: 12 ramps | 32.9 | 36.8 |
| Buccaneer Bay, two ramps | 57.9 | 59.3 |

These are short 1.5-second samples, not a minimum over a complete game. The
stress layouts deliberately overlap ramps; they measure overdraw, not design
quality. The console currently runs one physics update per rendered frame.
Expensive rendering therefore slows game time as well as LCD updates.

The first change moved rail traversal into SRAM. The final version keeps the
segment clipper in SRAM and writes fully visible, short ramp-floor spans as
packed bytes inside the existing SRAM beam walker. Generic clipping remains
the fallback at horizontal edges. It skips invisible floor rows and removes
a redundant path scan; no image cache or physics change is involved. Keeping
the generic path traversal in flash pays for the faster floor writer within
the hardware limits: 50,904 of 50,944 image bytes, 17,916 of 18,416 static RAM
bytes, with the 2 KB stack reservation separate.

Before/after comparison covers 31,176 complete LCD frames: 255,393,792 bytes
are identical, including all nine themes, 1/2/3/4/6/8/12 ramps, both horizontal
edges, scrolling, zoom and shake. The same native/WASM parity and seeded-play
checks still run. Work counters also include the direct packed spans; bypassing
the generic graphics call does not bypass the regression budget.

This is a partial recovery: Orbital Robot averages 58.7 rather than a locked
60 Hz, and heavily overlapping stress layouts still miss that target. Larger
caches or fewer repeated draws would require another measured design change.
Machine-readable camera sweeps and active samples are in
[`ramp-performance.json`](ramp-performance.json).

Reproduce with the matching firmware installed and the browser disconnected:

```sh
python3 Pinball/tools/benchmark_ramp_device.py --port /dev/cu.usbmodem101 \
  --stress-ramps 4 6 8 12 --out Pinball/out/ramp-performance/results.json
```

### Rendering options

| Approach | Benefit | Cost and constraints |
| --- | --- | --- |
| Run hot rail traversal in SRAM | Avoid repeated slow instruction fetches; keep identical art and live edits | Uses some of the limited remaining RAM; measure flash and stack headroom |
| Cull an entire invisible ramp before building its curve | Removes off-screen setup work | Does not reduce visible ramp overdraw; bounds must include the throat, shadows and arrow |
| Cache curve points when geometry changes | Avoids rebuilding the same Bezier paths | Needs bounded cache storage and invalidation on live edits; still draws every pixel |
| Pre-render transparent ramp overlays or row spans | Reuses deck, shadow and rail pixels | Must preserve ground-ball/ramp/riding-ball layers; RAM is too small for another full framebuffer |
| Generate compressed overlays on the SD card | Moves larger caches off RAM and keeps SD boards editable | Adds file format, I/O and invalidation costs; board, theme and renderer hashes must match |
| Decouple physics ticks from LCD frames | Preserves game speed when the renderer misses a frame | Does not restore smooth animation; requires capped catch-up and tick-scheduled input |

Pre-rendered art must be generated by the same renderer, not a second visual
implementation. The ramp deck/rails cover ground balls and flippers; riding
balls appear above the ramp. The floating arrow and HUD remain separate.

## Why mirrored keyboard controls can diverge

Studio and the console share C++ physics and light contact spin. The standard
`Scatter.h` disables all three synthetic angle variations. The parity tests
compare native and WASM state and pixels, and explicitly test seed-independent
motion with scatter disabled.

The live connection is currently a control mirror, not a synchronized replay:

- Studio queues a key transition immediately for its next 60 Hz physics tick.
- `DeviceKeyStream` sends transitions over USB in order, holding each state for
  at least 18 ms; the console samples the most recently received mask.
- Neither input messages nor their acknowledgements carry a target physics tick.
- An ordinary Restart independently chooses a new seed on each side. Shift +
  Restart reuses Studio's explicit seed, but does not align physics ticks.
- Board edits apply locally before the USB transaction finishes. SD operations
  pause the console while the browser simulation continues.
- Studio uses an accumulator driven by browser animation frames; the console
  currently advances physics once per hardware display frame. A slow renderer
  therefore changes the tick reached when a later USB input arrives.

Even one tick changes the flipper angle at impact. Subsequent collisions can
amplify that difference without any randomness.

### Options for exact trajectories

| Approach | Exact independent replay? | Trade-off |
| --- | --- | --- |
| Shared seed plus simultaneous Restart | No | Easy diagnostic; input arrival and edits still occur on different ticks |
| Replay inputs sampled by the console | Yes, with the same reset and build | Small optional input/frame trace on the console; the browser follows slightly behind without delaying console controls |
| Inputs and edits scheduled by tick | Yes, with the same initial state and build | Add session ID, target tick, ordered commands, acknowledgement of the applied tick, small input buffer, late-command handling and periodic full physics-state hashes |
| Console-authoritative browser display | One simulation is authoritative | Stream complete state/snapshots, including all balls and spin; the browser can render the full editor view but must reconcile any local prediction |
| Recorded tick-by-tick replay | Yes, offline | Best regression test; reproduces input and edit ordering without providing live synchronization |

To minimize changes to ordinary console play, prefer replay of inputs actually
sampled by the console. An explicitly enabled editor trace reports the sampled
button mask and numbered frame; the browser advances the shared simulation
from that trace rather than its own wall clock. The console continues normally
and never waits for a browser acknowledgement. Reporting is inactive during
standalone play. The trade-off is a slightly delayed browser view and some
additional firmware bytes; flash and RAM fit must be checked before implementing
it. This is a proposed protocol addition, not a shipped synchronization feature.

Start both from a reset with the same board bytes, physics/build fingerprint,
seed and released button state. Record accepted edits, pauses and restarts at
their actual application boundaries too; echoing buttons alone would still
diverge during editing. Use frame sequencing that continues during pause, not
only the frozen `game.ticks` counter. Include progress watermarks and detect
lost events or trace-buffer overflow. Compare state at equal step numbers,
not equal wall-clock times, and report divergence rather than silently
resynchronizing a test. A slower console can make the browser wait; it must
not change which step receives an input.

Visual frames need not arrive at the same instant for their physics states to
match at the same tick. Any local prediction used for responsiveness must be
clearly distinguished from authoritative comparison results.
